TCO Tree Content Agent:
Automating Support Tree Authoring

Drafting support tree node content manually (content recommendations, functional area questions, SAPROD-ready output) was the most time-consuming step in the TCO deflection workflow. I built a Claude Code custom agent pre-loaded with ISQM data, tree node structure, and domain knowledge to automate it.

2,753 Closed support cases analyzed
94.7% Cases with no doc coverage
17 ISQM patterns mapped to tree nodes
1 Agent. Built in one session.

Context

The TCO reduction workflow has a clear bottleneck: content authoring.

The problem

SAP APM has a Support Assistant Tree on me.sap.com: a decision tree that intercepts customer issues before they become support tickets. Each node holds content recommendations (help portal links, KBAs) and functional area questions that route the customer to the right resolution.

ISQM analysis identified 17 high-volume ticket patterns with little or no coverage in the tree. Most of the work is well-defined: pick a pattern, map it to the right tree node, draft content recs and questions in SAPROD format. The analysis is done. The authoring is the bottleneck.

Why it matters

94.7% of 2,753 closed cases had no documentation coverage at all: no KBA used, no help portal page referenced, no self-service path that worked. The tree exists to close that gap. But manually authoring each node (finding the right links, writing combobox question logic, formatting for SAPROD) takes time that compounds across 17 patterns.

A purpose-built agent that already knows the ISQM data, the tree structure, and the SAPROD format removes that friction. The work becomes: prompt, review, paste.

How the Agent Works

A Claude Code custom agent definition that ships with its own domain knowledge.

1

Agent definition file

The agent lives at ~/.claude/agents/tco-tree-content.md, a Claude Code agent definition with a rich system prompt. It embeds the full ISQM dataset, tree structure, node IDs, pattern-to-node mappings, and the exact SAPROD output format. Available globally in any Claude Code session.

2

Input: a pattern name

The user types a prompt like "Draft node content for Data Synchronization" or "Batch draft all HIGH-gap patterns under Integration and Connectivity." No data lookup, no spreadsheet, no copy-paste from ISQM first: the agent already has the context.

3

Output: SAPROD-ready content

The agent returns a structured block with content recommendations (type, title, link) and functional area questions (question text, combobox options) formatted to paste directly into the SAPROD node editor. It also flags when a new L2 subnode is needed and suggests a name.

4

Prompt cheatsheet built-in

The agent file includes a prompt cheatsheet: single patterns, batch drafts, gap analysis, new subnode suggestions, troubleshooting guide link-ups. The cheatsheet lives inside the agent definition so it never gets lost.

How to Invoke It

Built-in prompt patterns: from single nodes to full batch drafts.

Single pattern

"Draft node content for Rules Engine"
"Draft node content for API Access, focus on X-API-Key subpattern"

Batch draft

"Batch draft all HIGH-gap patterns under Integration and Connectivity"
"Batch draft the top 5 ISQM patterns"

Gap analysis

"What's the fastest deflection win, which single node should I build first?"
"Which patterns have no tree node coverage yet?"

Troubleshooting link-up

"Which ISQM patterns also need a troubleshooting guide entry?"
"Draft a troubleshooting entry for Event Mesh to pair with the tree node content"

What This Demonstrates

Building the agent was itself a documentation and content strategy act.

Domain knowledge as agent context

The agent's value comes from what's inside it: not general AI capability, but specific knowledge: ISQM ticket volumes, subpatterns, tree node IDs, output format constraints. Embedding that context is the same skill as writing good documentation: knowing what information matters, structuring it for retrieval, and designing outputs that match the downstream workflow.

Automation without losing authorial judgment

The agent drafts, the author decides. Content recommendations still need real SAP Help Portal links. Questions still need review for SAPROD combobox constraints. The agent removes the blank-page problem and the formatting work; the UAD applies domain expertise to refine and finalize. The workflow is faster, not bypassed.
