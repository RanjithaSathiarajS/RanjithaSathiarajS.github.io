UI/UX Review SAP Fiori Guidelines Technical Writing

UI Review: Implement Recommendations
— Maintenance Data Workflow

A structured review of labels, messages, and interactions across a 16-screen workflow in SAP Asset Performance Management, benchmarked against SAP Fiori guidelines and enterprise writing standards.

16 Screens reviewed
62 Findings logged
5 Systemic patterns
6 Finding categories

Context

What was reviewed and why.

Workflow

The Implement Recommendations — Maintenance Data workflow in SAP APM allows users to assign task lists and maintenance plans to a recommendation, or flag them as managed by an external system. The review covered the full user journey: from the list view through dialogs, confirmations, state cards, error messages, and status transitions.

Review criteria

  • SAP Fiori design guidelines
  • SAP enterprise writing standards (capitalization, articles, tone, tense)
  • UI labeling conventions (button labels, field labels, column headers)
  • Empty state, error message, and confirmation dialog patterns
  • Cross-screen terminology and label consistency

Findings by Category

62 findings grouped into 6 categories.

✍️

Writing Standards

18 findings

Incorrect capitalization of common nouns (Task List, Maintenance Plan), missing articles, wrong tense for persistent states, ambiguous connectors ("as", "since" instead of "because"), missing full stops.

🔘

Button & Label Naming

14 findings

Vague button labels ("Manage Externally", "Confirm", "Edit"), generic dialog titles ("Confirmation"), unclear field labels ("External Link:", "Management" column), and column values using adverbs as data ("Externally", "Internally").

⚠️

Error Messages

12 findings

Competing draft versions of the same errors, missing actionable next steps, run-on instructions, wrong prepositions ("set as" instead of "set to"), and references to UI labels that may change.

📋

Dialog Patterns

10 findings

Informal placeholder text ("Post a comment"), inconsistent primary button labels across dialogs (Confirm / Save / OK / Continue), and development artifact labels ("Dialog", "List Item") visible in the UI.

🗂️

Data & State Display

5 findings

Filter counts showing 0 with visible rows, incomplete table rows, unlabeled input fields, system-generated text auto-filling user comment fields, and view-mode cards with no editing affordance.

🔗

Terminology Consistency

3 findings

Undefined term "rule" introduced in error messages without definition; "Objects" vs "Items" used interchangeably in the same table; status label capitalization inconsistent across screens.

Before & After — Selected Examples

High-impact rewrites across labels, messages, and dialogs.

Empty state — Task Lists
Before

"No items available. When there are, you'll find them here."

After

"No task lists assigned. Use Create or Assign to add one."

Reason: Empty states must be concise and action-oriented per SAP Fiori guidelines. The original is conversational and non-directive.

Toast / success message
Before

"Valve Insert Removal & Seal Replacement's task list and maintenance plan is being managed externally."

After

"The task list and maintenance plan for RCMD_1234567 are now set to external management."

Reason: Plural subject requires plural verb; possessive form is awkward; "-ing" tense implies an ongoing action rather than a completed state change.

Info banner — Maintenance Plans section
Before

"Maintenance plan is managed externally, as Task List for this recommendation is managed externally."

After

"The maintenance plan is managed externally because the task list for this recommendation is set to external management."

Reason: "as" is ambiguous (means "while" or "because"); "Task List" incorrectly capitalized; missing articles; "because" makes the causal relationship explicit.

Error message — missing task list
Before

"Assign a task list before creating or assigning a Maintenance Plan."

After

"Assign a task list to this recommendation before creating or adding a maintenance plan."

Reason: "Maintenance Plan" incorrectly capitalized; "assigning" echoes "Assign" confusingly; "to this recommendation" removes ambiguity about scope.

Column values — Management column
Before

Column header: "Management" / Values: "Externally", "Internally"

After

Column header: "Management Type" / Values: "External", "Internal"

Reason: Column header is vague; adverbs are non-standard as data values — SAP uses adjectives or nouns for status/type column values.

Systemic Patterns

Issues that span the entire workflow and require a global fix, not a per-screen fix.

01

Button label inconsistency across dialogs

Five different primary button labels used across similar data-entry and confirmation dialogs: Confirm, Save, OK, Ok, Continue. SAP Fiori standard: use Save for data-entry dialogs, OK for information-only message boxes, and action-specific labels (e.g., "Switch to Internal") for irreversible state changes.

02

Competing error message drafts

Three screen sets (Screens 14, 15, 16) each show two different draft versions of the same error message — neither finalized. Indicates lack of a centralized message catalog and single-owner review process for error copy. Recommendation: establish a UAD-owned message catalog with one approved version per error scenario.

03

System text used as user comment content

The comment field in dialogs is auto-filled with system-generated state descriptions. When users edit the comment, the system explanation disappears — creating inconsistent state cards across sections. System descriptions and user notes must be separate, distinct fields.

04

Development artifacts visible in UI

"Dialog" section label and "List Item" placeholder text appear in production-bound screens. These are framework artifacts that must be removed before release. A pre-release UI copy checklist should include a scan for placeholder and default framework text.

05

Label references tied to a UI element name that may change

Multiple error messages reference 'Managed Externally' as a quoted UI label (e.g., "set it as 'Managed Externally'"). If the button or feature is renamed, all these references break. Error messages should describe the action, not quote the button label — making them rename-resilient.

Outcome

Deliverables

  • 62-finding review log with location, issue, severity, and recommended fix
  • Before/after copy rewrites for all high-impact labels and messages
  • 5 systemic pattern recommendations shared with the product team
  • Proposed button label standard for the feature

Impact

  • Identified 3 sets of competing error message drafts requiring alignment
  • Flagged development artifacts at risk of shipping to production
  • Surfaced undefined term "rule" — documentation gap now on backlog
  • Proposed a centralized message catalog to prevent recurrence
